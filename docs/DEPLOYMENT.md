Sign in with your own Render account and authorize repository access there; do not
send passwords, tokens or patient data to the agent. Review the proposed free web
service and create it. Any billing/account requirement must be handled by you.

Render builds the multi-stage Dockerfile: Node builds React, Python serves both
the built frontend and FastAPI from one origin. The health check is
`/api/v1/health`; `/assess`, `/clinical`, `/research` and `/protocol` are frontend
routes. Render supplies PORT. The service runs without root, without access logs,
and with public-sample mode enabled. No private datasets or model files belong in
the container, build context, Render environment or source repository.

Public mode offers nine predefined sample assessments and CSV/JSON downloads.
Arbitrary measurement uploads are rejected, even when a request claims to be
synthetic. Startup refuses private model configuration or patient import opt-in.
This public showcase is not an authenticated patient-processing service. Enabling
real records online requires a separate access-controlled deployment design and
applicable data permissions; do not toggle off public restrictions to achieve it.

After Render reports Live, open its returned HTTPS URL, select each sample and
check downloads, replay, research navigation and health. Do not claim deployment
success until Render supplies that URL and reports success. No live URL was
created by this agent: it has no authenticated Render account connection.
Docker image build was not verified here; source/API tests and frontend build
were checked. A successful local build does not prove provider deployment.

## Sample files and CSV ownership

These are independently authored, synthetic examples, available in both formats:
`stable-no-aki`, `stage1-rising`, `stage1-falling`, `stage2-observed`,
`stage3-observed`, `missing-vitals`, `delayed-result`, `micromol-units`,
`expired-reference`. Download via `/api/v1/samples/NAME/download?format=csv`
or `format=json`. They cover supported workflows; they are not every clinical
condition and do not establish clinical prediction accuracy. Files are generated
from source at request time, so no potentially real patient CSV is committed.

There are two different CSVs. The **measurement CSV** contains one encounter's
serial observations, reference and timing metadata; a researcher prepares it from
authorized clinical extracts, or a user follows the synthetic download template.
The **training CSV** contains one row per eligible first-Stage-1 index, with
patient-group, approved outcome and index-only features. It must be generated by
the authorized dataset pipeline, not manually fabricated from vitals or future
outcomes guessed by the UI. `LOCAL_TRAINING.md` gives the exact existing schema.

This project has not accessed MIMIC. Access belongs to the authorized researcher's
private environment. Raw MIMIC/eICU adapters, audited table mappings, protocol-based
cohort/label extraction and automatic export into the training CSV remain to be
implemented after dataset schema/version and clinical decisions are supplied as
reviewed aggregates. The researcher runs those scripts privately; the agent can
write source and synthetic tests but cannot inspect restricted records.
